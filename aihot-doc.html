01

它到底是什么

不是说「帮你做个新闻站」的脚手架，而是一套已经把精选流程、聚簇算法、热度排名和日报编排 全部跑通的完整引擎——网站、后台、每一步的提示词原文和入选门槛，都在仓库里。

  • 自己找热点：每天从一批信源收资料，大模型先筛一遍、再独立打两次分，挑出真正值得看的，写成中文标题和摘要。
  • 自己写日报：把不同来源说的同一件事聚成一个事件，按有多少人在说排出热点，每天早上出一份中文日报、每周周一出周报、每月 1 日出月报。
  • 换上你的行业就是你的站：把信源换成你的、把精选标准换成你的 KnowHow、把站名换成你的，它就是法律 / HR / 金融 / 黄金……你的行业热点站。
  • 提示词全公开、全可改：从浏览器里「该选 / 不该选」的判断逻辑，到写作口吻、事件归组，全部写在 `industry/prompts/` 里，改标准不用改代码。
技术栈：Node.js 24 · TypeScript · React Router（SSR）· Fastify · PostgreSQL 17 · pg-boss · Tailwind CSS · Docker Compose。 仓库自带 18 个公开的海外 AI 资讯源做示范——真正的信源，要换成你自己行业的。

03

六步精选链路

一条资料从信源进来，到变成首页的「今日精选」，要走完下面六步；每一步的提示词都在 `industry/prompts/`。

  • 采集：RSS / 网页列表 / JSON 接口 / X 账号 / 公众号 / 外部推送，六种方式把资料拉进来。
  • 预筛：先用宽召回的 `prefilter.md` 判断这是不是本行业的事，只拦明显无关的。
  • 两次独立评分：同一份标准独立打两次分（0–100），降低单次模型的随机偏差。
  • 写作：中文标题、答案先行的摘要、推荐理由、外文全文翻译，顺手把分类 / 标签 / 新闻事实抽出来。
  • 聚簇：和别的报道判断是不是同一件事，聚成一个事件，写进事件页综述。
  • 热点与成刊：分数过门槛、又不是精选里已有新闻的重复，才进精选；日报按规则编出当天要闻。
两次评分之和 ≥ 2 × 门槛 才够分（门槛按信源分级不同）。这一步决定了你的站「选得准不准」，详见第 08 篇的校准。
04

六种信源与三级分级

信源写在 `industry/sources.json`，首次启动导入；之后更常用的是后台「信源」页，能新建、试抓、调频率、暂停。

rss 订阅 web_list 网页列表 json_list JSON 接口 x_search X 账号 mp_account 公众号 external 外部推送
  • 分级决定门槛：T1 官方一手、T1_5 官方账号与准官方、T2 媒体与个人、EXCLUDE_MP 不参与精选——级别越高，入选门槛越低。
  • 同一家公司只算一个参与方：给信源填 `owner_entity_id`，避免一家公司的多个账号在热度里重复计数。
  • 全文默认关闭：只展示摘要和原文链接；只有来源明确允许时才打开 `site_fulltext` / `syndicate_fulltext`。
  • 中国大陆行业特别提示：一手信息常在公众号，公众号信源需要「极致了」的 key（按请求计费，有预算熔断）。
05

聚簇与热度

同一件事，官网发一篇、媒体转十篇、X 上吵一天，读者只需要看到一次——这就是聚簇和热度的意义。

  • 按事件而不是按文章：先用标题摘要的向量（没配向量服务时比文字重合度）在最近两周里找候选，再让模型判断是同一次发生、后续进展还是两件事。
  • 拿不准就合并：合并写入前再让模型复核一遍（复核可单独换一家模型，设 `GROUP_REVIEW_MODEL`）。
  • 热度按独立来源算：48 小时内每个独立来源只算一次，24 小时减半；重复抓取不会多算，一家媒体发十篇也只算一次。
  • 会「动」的榜单：和 6 小时前比，涨得快的标上升，新出现的标「新」——所以你看到的「当前热点」是一直在变的。
人工改过的事件归属不会被覆盖，事件页里「进展」和「报道」时间线还能一起切换「最新在前 / 最早在前」。
06

日报、周报、月报

每天出日报、每周一出周报、每月 1 日出月报；日报按规则编排（不调模型），周报月报从日报里汇编，模型只写总述和栏目导读。

  • 出刊时间可改：在 `site/site.ts` 的 `EDITION_TIMES` 里设置（排程每半小时检查一次，写整点或半点）。
  • 「一件事一条」：日报里同一事件只占一条；报过的事只在有新进展时跟进，不重复写。
  • 给 Agent 也能读：三种报告各自有 RSS、公开 API 与 MCP 出口，人和机器看的是同一份内容。
想看线上真实效果，对照一下 aihot.news 的「今日日报」排版——本指南的「AI 速览」页也正是用它的公开接口同步了同样的日报与热点数据。
07

改成你的行业

最省事的办法：把仓库丢给你的 Coding Agent（Claude Code / Codex 都行），让它照着 `AGENTS.md` 和 `docs/customize.md` 改。 要改的东西几乎都在 `site/` 和 `industry/` 两个文件夹，代码基本不用动。

  • 最值得花时间的是提示词：你对行业的判断经验就写在 `industry/prompts/selection-score.md` 里。建议先保留结构（五个维度加权、噪声压制、安全边界），只把「什么算重要 / 什么算噪声」的例子换成你的行业。
  • 改完跑检查：`npm run typecheck`、`npm test`、`node scripts/smoke.ts`，确认没有破坏框架本身。
署名提示：作者明确要求「请不要用原项目的名字和 Logo」——换上你自己的站名与图标，它就成了完全属于你的行业热点站。

  • 公开接口合规：个人非商业使用不强制界面署名，但机器响应里的来源、canonical 与原文链接必须保留并传递；用于收费产品或对外镜像需先取得授权。
  • 速率限制：公开只读接口对轮询有最小间隔要求（响应头里的 `Cache-Control: s-maxage` 指示了可缓存时长），请按建议的 User-Agent 与间隔访问。
  • 许可是 MIT：代码可学习、修改、非商业使用；原项目名字与 Logo 不在许可范围内。
