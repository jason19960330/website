01

它到底是什么

一个极轻量的个人自托管「Agent 自动化中台」，把任务调度做成零依赖内核，把其余全拆成插件。

  • 解决的是「人一走，活就断」：平时用命令行 Agent 要你输一句、盯着它跑、等它问下一步；关掉窗口事情就停了。它让事件（定时、Webhook、Issue、告警）自己进内核，Agent 在后台把活跟到做完。
  • 一台电脑、一条命令就能跑：装在自己的 Windows / macOS / Linux 上，不用买云服务器、不用开放公网端口、不需要 GitHub 账号；模型消耗走你本机已登录的 CLI 账号。
  • 没有后台界面：需要拍板时把卡片推到飞书、钉钉、企微、Slack、Discord 或桌面通知；想看全局进展敲一行 agent-autoloop status，也可以自己读 GET /v1/state 写页面。
  • 不绑定某一家 Agent：任何能「收提示词并打印最后一条回复」的命令行工具都能接，不需要 SDK、不用改 Agent 源码。TypeScript 编写，MIT 协议，Node.js 24 或更新。
  • 设计有六条原则：注意力最贵（默认安静）、一切都是事件、一切都连进来、Agent 就是一个进程、一轮不等人、规则才是指令。内核不主动连任何东西，凭据留在用它的插件里。
形态：一个本地后台服务 + 命令行工具（不是网站、不是 App）。仓库 2026-11-03 创建，四天内冲到约 3.8k star / 695 fork，源码约 8,080 行 TypeScript、247 个文件，其中内核约 1,850 行且零运行时依赖。
02

一轮任务怎么跑

五步走完，最妙的是「一轮不等人」。

  • ① 新事件进来：早上 9 点的定时任务、GitHub 新提的 Issue、业务系统报的错，都变成一条标准事件送进内核；你点卡片也是一条事件。
  • ② 按规则派活：内核照 rules.json 决定交给哪个 Agent、在哪个目录干；同一件事排队时又来的消息会合并成一轮处理。
  • ③ 干完一轮就退出：Agent 把结果写在最后一条回复里，进程直接退出，不占着后台干等。
  • ④ 拿不准才问你：碰到删数据、重启服务、花钱、对外发消息这类事，回执里附一段 agent-autoloop 代码块发起 ask，中台推一张带选项的卡片给你。
  • ⑤ 点一下接着干：你选完，它接上原来的对话把剩下的活做完。能自己搞定的事直接办完，或约个时间（如半小时后）再醒来复查，全程不打扰你。

03

安装与试跑

前置：Node.js 24 或更新、Git，以及一个已经登录的命令行 Agent；macOS / Linux 另需 curl。

安装 → 体检 → 真实走一遍「提问 → 退出等回复 → 拍板 → 接着干完」

{{ texts.install }}
  • Windows PowerShell：irm .../install.ps1 | iex；原生支持任务计划程序登录后台常驻，Win 10/11 都不需要管理员，退出 10 秒后自动重启，注销后停止。
  • 程序与数据分离：程序装进 ~/.agent-autoloop/app，规则、配置、日志留在 ~/.agent-autoloop；安装和 update 都取通过全部检查的最新 Release。
  • 默认开桌面通知：macOS 用 osascript、Linux 用 notify-send、Windows 用系统托盘；没有图形会话时安静跳过，问题仍能用 status 看到。
  • 试跑别跳过：try 会用你的模型额度真实跑一轮，非交互终端打印 answer 命令后退出是正常等待；把问题转给本人、回答后再 status，看到「试跑通过」才算接通。
  • 本地仓库安装：设 AGENT_AUTOLOOP_REPO=/绝对路径 后运行本地 install.sh，适合开发调试；临时 HOME / CI 环境加 --no-service。
卸载：agent-autoloop uninstall 只停服务、删自己的命令与 Skill 链接，默认保留规则、密钥和记录；--yes 仅跳过确认。
04

写规则 rules.json

不需要写胶水代码，一条规则只回答五件事：什么事件、交给谁、在哪、照什么做、要不要告诉你。

~/.agent-autoloop/rules.json 示例 + 常用命令

{{ texts.rules }}
  • 定时与外部事件写法一致：when 用 cron 就是定时，用 source + types 就是外部事件（先在 sources 登记来源）；to 填 agents 里已有的名字。
  • 并发与会话：parallel 让同一对象的事件互不等待（还受 worker.capacity 限制，默认 2）；把批量规则写进同一个 group 留出名额给对话；resume: true 让新事件接着上一轮会话，默认每次开新会话。
  • 先问清单：askFirst 默认列了删数据、停服、花钱、对外发消息，只有这几类事才先问你；暂停规则用 pause <规则>，恢复用 resume，立即跑一轮用 run，都不改 rules.json。
  • 改错了也不怕：保存后几秒自动生效；文件写错、被删或读不到，系统继续按旧规则跑并发卡片提醒。check 校验、rules explain 看生效规则和下次定时、emit --dry-run 预演一条事件会派给谁，后两个只看本机文件、不连中台。
  • 长期任务配一个 Skill：手册里写清「怎么算做完、怎么核实」，不用写怎么结束一轮；建议项目里放 docs/decisions.md 记你定过的事、docs/declined.md 记拒绝过的，让 Agent 先读，定过的不再问。
本项目自带一份正式的 SKILL.md（在 skills/agent-autoloop/），安装时也会提供给 Agent 使用，用来配置规则、接插件、部署服务器和查日志——这也是它和「一堆 shell 脚本」的区别。
05

四向插件体系

事件来源、Agent、通知通道、甚至 CI/CD 交付流水线，四个方向都能自由替换。

  • 事件（怎么发现新活）：内置 GitHub / GitLab Webhook、HTTP 接口、cron 定时、Issue 轮询脚本；对方推不过来或中台在家里，就定时跑脚本轮询。
  • Agent（谁来干活）：内置 Claude Code、Codex、ACP、DeepSeek Harness、通用命令；会说 ACP 的 Gemini CLI / OpenCode 也能接，并支持跨进程续接原会话。
  • 通道（去哪找你拍板）：桌面通知（默认开启）、飞书（官方 lark-cli，支持按钮回调和卡片更新）、钉钉 / 企微 / Slack / Discord 的 Webhook 模板；文字通道靠回答链接拍板，需配 hub.publicUrl。
  • 交付（把 CI/CD 也做成插件）：给 GitHub PR 打上 deliver 标签后自动走「审代码 → 等 CI → 合并 → 等部署 → 核对线上版本」；审查和交付配置只从 main 读取，绝不在接单电脑上检出或运行 PR 代码。
  • 第三方插件：agent-autoloop add <git 地址> 克隆到 ~/.agent-autoloop/plugins/；仓库根目录放 agent.ts / channel.ts / source.ts 即可，插件是可信本地代码，先读再装。

06

八套拿来即用的场景

每套模板都带规则、任务 Skill 和写明权限原因的启用说明，从例子改，别从零写。

  • 每日早报：默认每天 8 点整理本地笔记和 Git 提交，写入 briefs/YYYY-MM-DD.md；收件箱分诊：读过去 24 小时未读邮件写成清单与回复草稿，不发送、不改邮箱状态。
  • 跟进 GitHub Issue：每 5 分钟查新 Issue，在本地改代码并通知你查看，不提交、不推送、不回复 Issue；PR 自动交付：打 deliver 标签后一路跟到上线核对。
  • 线上告警排查：接收报错、对照代码查原因，需要重启时发卡片询问，回答后继续；网站巡检：每 5 分钟查状态和关键内容，持续异常不重复通知，恢复后更新原卡片。
  • 用户反馈处理：重读反馈当前状态、修复、交付核实、准备回复；飞书周报与业务摘要：周日 18 点按你的权限读汇报和表格，完整稿留本机、飞书只发简短摘要。
  • 还有更多：Claude 委托 Codex 处理网页（浏览器交接）、每周代码清理、交付 PR 三套独立任务手册与最小插件模板 hello-agent / hello-channel / hello-source。
启用三步：把任务 Skill 放进所用 Agent 的 skills 目录 → 把示例规则合入 rules.json 并替换电脑名和路径 → 运行 agent-autoloop check。反馈、巡检、飞书摘要和收件箱分诊默认使用北京时间、只发本人飞书私聊；样例数据全是虚构的，脚本只用本地 HTTP 与假飞书 CLI 验证过。
07

内核四个机制与实测

把四个计算机领域的成熟做法，搬到了命令行 Agent 上。

  • 挂起零消耗：等你时进程退出、状态落库，回答后接回原会话；事件溯源：所有状态从一条只追加的日志算出，日志和索引同一事务落盘后才应答，强杀不丢已确认事实，why 42 查任意一轮来龙去脉。
  • 指令数据分离：思路和 SQL 参数化一样。Issue 标题正文等外部文字只作为资料放进文件，不拼进提示词；用哪个 Agent、在哪个目录、什么权限只由本机规则决定，事件里夹带 cwd / agent / access 字段会被直接拒收。
  • 跳数熔断：类似网络包 TTL，Agent 交回的事件再派给 Agent 时层数累加，经过人工提问和定时复查也不清零，超过 8 层只记录、不再派活并发卡片告诉你。
  • 确定性内核：约 1,850 行、零运行时依赖，不读系统时钟、不用随机数、不向外发请求，同样的输入永远得出同样的结果；插件主动连进来，账号凭据留在各自插件里。
  • 实测（M5 Pro / Node 24）：冷启动 88.78 ms、空闲内存 59.94 MB、持久化 2394 条/秒、派活 p99 1.82 ms、110 万条事实启动 99.8 ms；格式变化后首次全量重建 110 万条用 43.1 秒。
  • 测试很硬核：88 个测试文件，含 20 万步随机模拟（断网、丢包、崩溃、重复提交，一个种子可复现）、1000 次 SIGKILL 强杀验证、变异检查，以及 Windows / Linux / macOS 三平台 CI。
边界诚实：作者明说这些验证覆盖的是「进程崩溃和有限场景」，不等同于断电恢复证明或完整安全审计；历史变大后状态汇总会变慢，日志和索引也继续占磁盘。
08

安全边界与适用判断

什么时候该装、有什么门槛，以及必须先知道的红线。

  • 默认只听本机：要对外必须在前面放做 HTTPS 的反向代理；macOS / Linux 数据目录设 0700，Windows 用 ACL 只留当前账号与 SYSTEM，数据库、事件正文和运行输出不向其他系统用户开放。
  • 不碰你的登录凭据：只启动你自己安装、自己登录的官方 CLI，不读取、不转存、不中转账号凭据；但作者坦承指令数据分离挡不住所有提示注入，默认权限是 edit，给 full 前要三思。
  • 卡片链接持有即授权：谁拿到链接谁就能回答那张卡片，7 天内有效，只发给配了 "links": true 的通道——绝不能转发到公开位置或共享群。备份里有主密钥和配置密钥，要和密钥一样保管。
  • 合规提醒：高频自动化建议改用 API Key，个人订阅额度主要是为日常人工交互设计的；本项目是独立开源项目，与 Anthropic / OpenAI 无隶属或背书关系。
  • 门槛要算清：Node 24 要求偏高、没有 Web 界面、卡片走文字通道需配可访问的 publicUrl；四种 Webhook 模板只在本地模拟服务验证过、没连真实 GitLab，场景样例数据全是虚构的，项目本身才创建几天。
  • 适合谁：想让本地 Agent 定时干活又不想被频繁打扰、能接受命令行、重视「数据留在本机」的人；不适合想要开箱即用图形界面、或需要团队级权限与审计的场景。
建议的上手姿势：先在 --no-service 的临时环境里跑通 try，用假通知程序验证，别一上来就接真实飞书应用或生产仓库；确认行为符合预期后再写第一条规则和接通道。
