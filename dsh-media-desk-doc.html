01

它到底是什么

一个装在 DeepSeek Harness 侧栏里的本地创作工作台，不是独立 App，也不是 DeepSeek 官方产品。

  • 给日更的人做的：作者是小红书科技博主「蜗牛的科技笔记」，把「灵感记不住、成稿太慢、发完不知道效果」三件自己踩过的事做成一个工具；社区插件，与 DeepSeek 无关，脚本由你在 Harness 里配置的模型生成、按自己的账号计费。
  • 五个页面组成闭环：灵感（记）→ 内容 / 成稿（写）→ 排期（发）→ 复盘（看数据）→ 风格（定调子），复盘提炼出的规则再回灌到写作提示词里。界面中英双语，默认跟随 Harness 语言，切到英文后脚本、标题、分镜也用英文写。
  • 一个包两个半片：cordis.patch.yml 声明同一个 npm 包既提供 Node 侧 Host 逻辑（src/host.js），也提供浏览器界面（dist/client.js）；运行时注册 /media-desk 前缀路由，前端通过它读写数据。
  • 数据全在本机：~/.dsh/media-desk/state.json 存所有内容，桌面版与网页版共用同一份；没有云端、没有账号系统，卸载插件也不会删数据。成稿可导出成文件夹，默认落在 ~/Documents/自媒体工作台/。
  • 支持 9 个平台：公众号、小红书、抖音、B 站、视频号、TikTok、Instagram、YouTube、X。2.6.1 补上四个海外平台，2.6.2 又加入 GPT 订阅生图与助手自选模型。
体量：2026-11-02 首次开源，11 天内连发 8 个版本（当前 2.6.2），约 941 star / 88 fork / 4 个 open issue，MIT，JavaScript。源码 110 个文件，src/ 约 4,126 行、client/ 约 4,615 行、7 个测试文件约 1,676 行。npm 包名就是 dsh-media-desk。
02

一键成稿怎么跑

整页一起长出来：文字与图片并行开工，每画完一张就落盘。

  • 流水线分三段：先写文章/脚本，再做标题与画面规划（normalizePlan 只取白名单字段，配图数与分镜数按设置截断），最后并发画封面、配图和六格分镜。默认 1 张封面 + 2 张配图 + 6 张分镜 = 9 张图，数量可调。规划里带 facts 事实清单，脚本提示词会带上这些已核对的数字，避免前后不一致。
  • 任务跑在 Host 进程：关掉页面也不会中断；每生成一张图就写一次盘，重启后把卡住的任务标记为「已中断」。并发上限 3，文字超时 240 秒后改用草稿，429 限流按 6 秒 / 14 秒退避，最多重试三次；单张图失败不影响其余，可单独重画。
  • 说一句就改，且只重画该重画的：applyRevision 接受标题、封面大字、脚本局部替换 / 整篇重写、某一镜的画面描述与图注，返回回执和需要重画的 targets；序号越界的修改直接丢弃。脚本里找不到要替换的文字会明确报错，不会静默失败。
  • 没接生图也能用：脚本、标题、分镜文案照常生成，视频封面退化成大字合成的纯文字版；连文字模型都没配时给「结构草稿」，并在界面上明确标注「未连接模型」，而不是假装成功。
  • 拿走就能用：脚本可直接编辑、一键复制；或把脚本、分镜脚本、封面、配图、分镜图一起保存成一个文件夹。视频封面由浏览器合成（画面叠大字），Host 只接受 JPEG 并校验文件头。
常用修改指令：「表达再直接一点」「第 3 镜换成俯拍」「封面字更有冲击力」「标题别超过 20 个字」。每一步都能撤销，而且撤销是三方合并式的 —— 只撤回这一步改过的字段，之后生成的成稿、画好的图不会被连带退回去（最多保留 30 步）。
03

三步上手与花费

前置：Node.js ≥ 20 与 DeepSeek Harness 0.2.1-rc.5 及以上的 0.2.x（已在 0.2.2-rc.1 桌面版与网页版测过）。

安装 → 更新 → 打开 → 清示例数据 → 卸载

{{ texts.install }}
  • 最省事的方式：桌面版「插件 → 添加插件」直接填包名 dsh-media-desk。命令行装桌面版要先完全退出（⌘Q）再装、装好重开；网页版装完重启 dsh web。终端里没有 dsh 就先在桌面版菜单选「管理 dsh 命令」。首次打开全是示例数据，点右上角「示例数据 · 清空」换成自己的。
  • 插件免费、不带密钥：写脚本用 Harness 里已配好的模型；不接模型只能出结构草稿。生图要自己的 API Key 或 DSH 已注册的订阅生图工具；不接生图，封面变纯文字版。导入自己的账号才需第三方 Monid，按次计费（小红书约 0.02 美元一个账号，抖音 / B 站 / TikTok / Instagram / X 不到 1 美分）。
  • 生图两条来源：默认 http，兼容任何 OpenAI 图片接口 POST {地址}/images/generations，设置里预填 OpenAI、xAI、火山方舟、智谱、硅基流动，也可自定义，填完点「试画一张」就知道通没通；或切到 tool 复用 dsh-plugin-subscriptions 注册的 image_generate（GPT 订阅生图），不用另填 Key。
  • 离线安装：到 Releases 下载 dsh-media-desk-*.tgz，把命令里的包名换成 "file:$PWD/dsh-media-desk-版本号.tgz"；卸载把 add 换成 remove dsh-media-desk。

设置文件结构与两种生图来源（密钥只存本机，权限 600）

04

五个页面怎么用

记 → 写 → 排 → 看 → 定调子，每一步都留在同一份 state.json 里。

  • 灵感：文字、链接、图片、视频、金句贴进来就是一张卡片，散落在无限画布上或切成按时间排的信息流。中间输入「agent」回车，新灵感记下的同时，以前提到 agent 的旧灵感会按相关程度挪到它旁边 —— 这是 client/related.js 的本地分词加权算法（英文按词、中文按连续字串加相邻两字，标题权重最高），不花模型额度。右边还有个助手：「把今天最好的灵感一键成稿」「接下来有什么排期」一句话就办。
  • 内容 / 成稿：所有稿子按灵感、成稿、待发布、已发布排成看板；点开任意一条进入成稿工作区，左边对话右边稿面，脚本可编辑可复制。
  • 排期：一张日历两件事 —— 每天一张灵感邮票记录连续天数，做好的稿子从右边拖到某天就排好了；排上即变成「待发布」，取消排期退回草稿，已发布的不动。右上角永远是下一条要发的内容。
  • 复盘：手动录入、粘贴 CSV，或导入自己账号。看一句话总结、每日播放、平台分布、表现最好的内容；从数据里提炼出的建议点一下就写进写作规则，规则还能导出成 Harness 的 Skill。
  • 风格：8 个板块 15 种博主预设（科技数码、旅行探店、Vlog 生活、观点认知、干货教程、种草测评、情感故事、热点资讯），中英各一套；也可导入自己账号或贴几篇旧稿，提炼成专属风格卡，随时改。normalizeStyle 只留白名单字段，风格会变成写作要求进入提示词。

05

插件架构与工程实现

Cordis 插件 → /media-desk/* 路由 → 浏览器半片，一个 npm 包同时装两个半片。

  • Host 侧 src/ 共 18 个模块：host.js 注册路由与鉴权，store.js 持久化与撤销，ops.js 唯一写入口，produce.js 成稿流水线，ai.js 调宿主 llm.prepareCall() 流式出字，images.js / image-tool.js 两种生图后端，intents.js 本地意图，harvest.js 抓链接，monid.js 账号导入，learn.js 复盘与 Skill 导出，settings.js / style.js / style-presets.js / seed.js / i18n.js / en.js / export.js。
  • 浏览器半片 client/：React + JSX 手写组件（canvas / studio / chat / schedule / insights / style / content / settings / modelpick …），scripts/build.mjs 用 esbuild 打成 CommonJS，react 由宿主提供、CSS 内联成字符串，包进 window.__ModuleLoader__.load() 的 lazy 模块。
  • 模型与工具都走宿主公共接口：ctx.get('llm') 取模型、ctx.get('agentDefaultModel') 读默认选择、ctx.get('tools') 执行订阅生图；不引用订阅插件内部模块，不读取登录凭证，也不伪造聊天会话。宿主拿不到鉴权服务时，requestRejection 一律返回 403。
  • 唯一写入口是硬规矩：界面操作和模型输出都汇到 applyOps，字段类型、长度、状态枚举、平台枚举、媒体路径全做白名单收敛；原型链上的属性名会被拒绝，单个操作失败不影响同一批里的其余操作，每一步都产出人话回执。
  • 多进程与撤销：Store 每次写入前按 mtime 判断是否要重读，桌面版和网页版可以同时开着；revertChange 做递归三方合并式撤销，保留之后的操作结果。示例数据与用户内容分开标记，切换中英只换示例文字、清空示例不会删预设。

06

安全边界与密钥

README 只用一句话概括，但代码里做得很细：把模型输出和外部内容都当不可信输入。

  • 逐请求鉴权：Web 服务不会替插件路由鉴权，所以每个 /media-desk 请求都自己走一遍 Host 的 connection.requestRejection()；拿不到鉴权服务就一律拒绝。所有写操作还检查 sec-fetch-site，拒绝跨站请求。
  • 防 SSRF 与路径逃逸：粘贴的链接、抓取时的跳转、生图返回的图片下载地址都要过 assertPublicUrl，本机与内网地址一律拒绝；静态文件只认 ^[\w.-]+$ 的文件名；订阅生图返回的路径必须 realpath 后落在 plugins/subscriptions/images/ 目录内，且有界读取、校验图片 MIME 与大小上限 40 MB。
  • 密钥隔离：图片 API Key 只写本机 ~/.dsh/media-desk/settings.json，文件权限 600，不进内容数据、不返回浏览器、不发给文字模型；空密钥表示「不修改」，只有显式 clearKey 才删除；错误信息里也不带密钥。Monid 用 execFile 调用本机命令，不经过 shell，密钥由 monid keys add 自己管。
  • 模型输出收敛：只取固定字段、限制长度、操作走白名单；视频封面只接受 data:image/jpeg;base64 并校验 JPEG 文件头；produce/reveal 的路径只从保存记录读，不接受请求里传的路径。账号 ID 只认固定格式，主页链接只认平台自己的域名。
  • 工具链不被绕过：订阅生图只认两个固定工具名，还要求默认执行器公布「可直接调用」；纯 Code Mode / PTC 执行器会被检测为不可用，避免用 run_code 绕过宿主全局工具策略。工作台是独立后台操作，不继承当前聊天会话的权限与历史开关。
隐私提醒：导入账号链接会发给 Monid 及其数据服务商，只能读公开内容，且仅限自己的账号，请先确认符合平台条款。漏洞请走 GitHub Security Advisories 私下报告，不要开公开 issue。
07

复盘如何变成写作规则

这是它最不像「套提示词的表单」的地方：数据进来，规则出去。

  • 三类信号：proposeRules 会用真实指标（示例数据不算）算出表现最好的平台、发布时段，还会统计你每次改草稿时是删短了还是扩写了；由此生成带 evidence 证据说明和 confidence 置信度的规则提案，例如「初稿写短一些」「以后标题不要超过 20 个字」。已有同名规则不会重复提案，没有数据就不提案。
  • 点一下就生效：提案通过 skills/learn 写成 proposed 状态的 Skill；激活后 stylePrompts 和成稿提示词会带上这些规则，之后每篇都遵守。仅由示例数据算出来的建议也会被标成示例，清空示例时一起清掉、不会被导出。
  • 还能带出工作台：skills/export 把非示例、状态为 active / exported 的规则导出成 DeepSeek Harness 的 Skill 文件（写到 ~/.dsh 下），导出后状态改为 exported。等于让这个工作台越用越贴合本人，且成果可以迁移。
  • 数据口径诚实：没有播放量的平台（小红书、抖音）改按互动量排序；computeInsights 会区分「只含真实数据」和「含示例数据」两种口径，避免示例把统计带偏。
和本站其他卡片的关系：之前整理的 dsh-context 讲的是这个宿主（DeepSeek Harness）本身，Agent Autoloop 的 README 里也把 dsh --profile headless 列为可接入的 Agent —— 三者属于同一条生态链：Harness 提供模型与插件系统，工作台把创作流程做成插件，Autoloop 负责让它定时自动跑起来。
08

限制与适用判断

什么时候值得装，以及必须先知道的几条边界。

  • 不能直接发布：各平台没有统一接口，只能复制脚本或保存文件夹后自己发。保存目录含脚本、分镜脚本、视频封面、配图和分镜图。
  • 账号导入有缺口：只支持自己的公开主页，支持小红书、抖音、B 站、TikTok、Instagram、X；公众号、视频号、YouTube 暂时导不了（仍可照常排期，风格可贴内容提炼）。小红书正文约 100 字、抖音只有文案、B 站大多只有标题，且小红书与抖音读不到播放量，提炼出的风格建议手动改。
  • 单机单人、无云同步：内容全在 ~/.dsh/media-desk/，换设备要自己搬；桌面版与网页版共用同一份数据是优点，但也意味着多机协作、团队审核这类需求不在设计范围内。
  • 强绑定宿主版本：依赖 DSH 0.2.1-rc.5 ~ <0.3.0，宿主升到 0.3 就要等适配；项目才开源 11 天、8 个版本密集迭代，2.6.1 才刚补海外平台，成熟度要按「个人作者的高强度自用项目」看。好消息是作者修 issue 与合并社区 PR 很快，README 专门列了 7 位贡献者及各自修的问题。
  • 适合谁：已经在用 DeepSeek Harness、需要高频产出图文 / 口播脚本的个人创作者；愿意把灵感、排期、数据沉淀在一个地方，且接受「生成只是初稿，最终还得自己改」的人。哪怕完全不接生图、不接 Monid，纯文字链路也完整可用。
  • 不适合谁：不用 DSH 的人、想要自动发布或多端云同步的团队、期待一键出成品不愿改稿的人，以及需要严格长期版本稳定的生产环境。
建议姿势：先只装插件、不填任何密钥，用示例数据把五个页面点一遍，确认「记灵感 → 一键成稿 → 说一句改 → 拖到日历」顺手；再决定要不要接生图 API 或订阅工具，最后才考虑 Monid 导入账号。清空示例后内容就完全属于你自己了。
