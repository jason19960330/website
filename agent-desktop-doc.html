桌面自动化 · 使用指南

Agent Desktop 完整指南

Vercel Labs 出品的给 AI Agent 用的桌面操作 CLI：不截图、不做像素匹配， 直接读 macOS / Windows / Linux 的系统无障碍树，把界面变成带 ref 的 JSON。 Agent 靠 ref 点击输入、再读一次界面验证结果。项目本身不含模型，循环跑在调用的 Agent 里。指南整理自其公开仓库。

01

它到底是什么

一个把桌面 GUI 翻译成结构化 JSON 的工具，不是 Agent、不是浏览器自动化框架。

  • 不用截图，也不用猜坐标：读操作系统的无障碍树（macOS 的 AX API、Windows 的 UI Automation、Linux 的 AT-SPI），把窗口、按钮、输入框、菜单按 role / name / value / states 返回成 JSON，每个可操作元素带一个 ref。
  • 项目不含大模型：官方 AGENTS.md 写得非常直白 ——「agent-desktop is a tool that AI agents invoke, not an agent」。观察、动作、验证的循环完全由调用它的 Agent 决定，它也没有 GUI 或交互提示。
  • 两种调用形态：命令行 CLI（每条命令输出一行 JSON envelope，日志走 stderr），以及随 Release 发布的 C 库 libagent_desktop_ffi，可以在进程内嵌入，二者共用同一套 core 语义。
  • 默认 headless：ref 动作走语义化的无障碍 API，不抢焦点、不移动光标、不合成按键、不碰剪贴板；没有语义路径就 fail closed，物理输入必须显式加全局 --headed。
  • 明确的能力边界：不自动化网页（官方建议改用 agent-browser），也看不见没有暴露无障碍树的 UI；它只做「看见并操作真实桌面应用」，不做任务规划、不做推理。
体量：Vercel Labs 出品，Rust 编写，Apache-2.0，创建于 2026-02；当前版本 1.2.0（2026-11-05），约 21,035 star / 1,560 fork / 208 个 open issue，文档站 agent-browser.dev/desktop。发布节奏很密，1.0.0 之后 9 天连发 5 个版本。
02

观察·动作·验证循环

四步一轮，「读一次不算数，必须再读一次确认」是它的核心纪律。

  • ① 观察：snapshot --app 应用名 -i 只留可交互节点；界面密集时先 snapshot --skeleton -i --compact 画三层浅图，再用 --root @sid:eN 下钻某个区域，下钻会把新 ref 加进同一个 snapshot id。
  • ② 动作：click @s8f3k2p9:e12 这类命令必须带快照前缀；裸 @e12 直接返回 INVALID_ARGS。动作前会做严格重识别：0 个匹配给 STALE_REF，多个匹配给 AMBIGUOUS_TARGET，绝不猜。
  • ③ 验证：ok: true 只表示命令返回了结果，不代表界面效果发生。用 wait --element ... --predicate value 或重新 snapshot / get 独立确认；异步步骤禁止用固定 sleep 后再读，那是竞态。
  • ④ 判定：动作结果带 data.disposition（delivery + retry）。只有 retry: safe 才能重试或换动作；unsafe / unknown 时先观察界面再决定，重复一次可能提交两次、或把 toggle 又拨回去。
  • 密集应用怎么省 token：find 在你已经知道 role 或精确名字时更省；菜单、sheet、alert 这类 surface 本身已聚焦，不要再 skeleton；动作返回 data.surfaces 时接着操作新出现的浮层。

03

安装与首次运行

前置：Node.js 18 或更新；npm 包自带 x64 / ARM64 原生二进制与平台 helper。

安装 → 体检 → 加载当前平台指南 → 第一次观察

{{ texts.install }}
  • macOS / Linux 还可以用 Homebrew：brew install agent-desktop，公式在 Homebrew/homebrew-core 默认目录；官方没有 Scoop 包，也不再维护自定义 tap / bucket。
  • 安装脚本被拦时：npm 12 默认拦 postinstall，此时每次调用会多走一层 Node launcher、约多 125 ms；可用 npm install -g agent-desktop --allow-scripts=agent-desktop 放行，或直接从 GitHub Releases 下载原生压缩包（记得把 helper 放在可执行文件旁边）。
  • 平台要求：macOS 13+（需辅助功能授权，截图另需屏幕录制）、Windows 10 1809+（同权限级别无需授权，但读管理员程序需提权的 Agent）、Ubuntu 24.04+ / glibc 2.35（需 at-spi2-core，且必须在用户图形会话里运行）。
  • 从源码构建：Rust 1.89.0（rust-toolchain.toml 固定）+ C 工具链，cargo build --release -p agent-desktop；平台 crate 只能在自身 OS 编译，macOS / Linux 还要单独构建 helper 并与 CLI 放同一目录。
  • 校验发布包来源：checksums.txt 只能查损坏，不能证明出处；用 gh attestation verify <archive> --repo vercel-labs/agent-desktop 验证构建来源。
Linux 特别注意：TTY、SSH 或缺少该会话 bus / display / runtime 环境的容器都看不到应用；agent-desktop status 里 supported_surfaces 为空就说明无障碍总线没应答。按键在 X11 需要 XTEST，在 Wayland 需要 GNOME Mutter RemoteDesktop，剪贴板还要 wl-clipboard。
04

60 个命令怎么分组

60 个命令名里 56 个可实际操作，另外 4 个是「按住不放」类，在守护进程支持前一律拒绝。

  • 观察：snapshot、find、get、is、screenshot、list-surfaces；get --property value 与 text 语义不同，别混用。
  • ref 动作：click、double-click、right-click、type、set-value、clear、focus、select、toggle、check / uncheck、expand / collapse、scroll、scroll-to。
  • 键鼠与应用窗口：press、hover、drag、mouse-*，以及 launch、close-app、list-apps、list-windows、focus-window、minimize / maximize / restore、open-system-surface。
  • 其余辅助面：通知（list-notifications、notification-action 等）、剪贴板（clipboard-get/set/clear）、wait、session / trace / cursor-overlay，以及系统组 status、permissions、version、batch、skills。
  • 敏感文本走管道：type、set-value、clipboard-set 支持 --stdin，避免内容出现在进程参数里；batch 的 JSON 文本会进进程参数，涉密步骤要拆成单独命令。
  • PowerShell 有坑：裸 @token 是 splatting 运算符，每个 ref 都要写成 '@s8f3k2p9:e8'；环境变量用 $env:NAME，解析 JSON 用 | ConvertFrom-Json。
别加 clicked / moved 这类成功标志：从契约 2.5 起，13 个返回 OperationReport 的命令移除了所有「每次成功都带上」的布尔标志，改由 disposition、steps、target 说明到底发生了什么 —— 一个永远为真的标志证明不了任何事情。
05

Skills 与 MCP 接入

两种给 Agent 用的方式：随二进制发布的 Skills，以及 1.2.0 新增的 MCP server。

Skills 启动三条 + MCP 配置 + AGENTS.md 写法

{{ texts.mcp }}
  • Skills 编译进二进制：skills get desktop 给循环、refs、验证与重试规则，skills get platform 自动返回当前 OS 的差异指南；还有 macos / windows / linux / ffi 专用 skill 和可选助手 jev-desktop。因为随版本发布，永远不会出现文档与二进制对不上的情况。
  • 按需加载参考手册：skills get desktop workflows 这类写法只取一篇 reference（commands-observation / commands-interaction / commands-system / workflows），不必把整套手册塞进上下文。
  • 装到 Agent harness：npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop；也可以直接把 skills/agent-desktop/SKILL.md 放进 WorkBuddy 的 ~/.workbuddy/skills/agent-desktop/ —— 它的 name + description frontmatter 格式兼容，前提仍是本机已装 CLI 并授好权限。
  • MCP 一一映射：agent-desktop mcp 运行时读 CLI 命令树，每个 leaf 命令变成 desktop_* 工具（snapshot → desktop_snapshot，session start → desktop_session_start），schema 直接来自 clap 参数与帮助文本，调用返回同一个 JSON envelope。
  • 全局 flag 只在启动时给：agent-desktop mcp --session s1 --headed 对每次调用生效，单个 tool 不能设置全局 flag；--wait-for 也不能逐次传。最多 8 个并发调用，拒绝超过 4 MiB 的消息，取消时先 SIGTERM 让按住的键/按钮释放。
和本站其他卡片的关系：它补的是「Agent 怎么可靠地操作桌面 GUI」这一层；之前整理的 Agent Autoloop 补的是「什么时候让 Agent 干活、怎么挂起等人工拍板」，两者正好是上下游。MCP 文档提醒：这个 server 的权限等同于「以当前登录用户身份运行的 shell」，请保持客户端的动作确认，并把屏幕上读到的文字当作不可信输入。
06

JSON 契约与错误恢复

契约版本 2.6：每条命令只输出一行 envelope，按 code 与 disposition 分支，绝不按 message 分支。

成功 / 错误 envelope 示例 + 判断是否重试的顺序

{{ texts.contract }}
  • 字段与省略规则：version / ok / command + data|error；None 字段和空数组一律省略，缺 key、null、[] 要同样对待；ref_count 与 tree 永远在 data 里，快照必带 data.complete。
  • 16 个错误码：PERM_DENIED、ELEMENT_NOT_FOUND、APP_NOT_FOUND、ACTION_FAILED、ACTION_NOT_SUPPORTED、STALE_REF、AMBIGUOUS_TARGET、WINDOW_NOT_FOUND、PLATFORM_NOT_SUPPORTED、TIMEOUT、INVALID_ARGS、NOTIFICATION_NOT_FOUND、SNAPSHOT_NOT_FOUND、POLICY_DENIED、APP_UNRESPONSIVE、INTERNAL。
  • 四档 delivery：not_delivered（唯一 retry: safe）、delivery_uncertain、delivered_unverified、delivered_verified 均为 unsafe，unknown 保持 unknown。读命令的失败和参数拒绝一律是 not_delivered。
  • recovery 只在 safe 时出现：refresh_snapshot_then_retry_original（STALE_REF / SNAPSHOT_NOT_FOUND）、inspect_state_then_retry_original（TIMEOUT / APP_UNRESPONSIVE）、request_explicit_policy_then_retry_original（POLICY_DENIED）；ACTION_FAILED / AMBIGUOUS_TARGET 永远不带 recovery。
  • 退出码：0 成功或 help/version，1 结构化错误（envelope 仍在 stdout），2 命令行解析错误。裸 @e1 这类「解析器收下、命令拒绝」的参数是 1，缺参数才是 2。
  • 契约在变：2.1 去掉 error.retry_command 字符串（改成结构化 recovery），2.2 允许 partial snapshot 成功返回，2.5 移除成功标志，2.6 收紧 Windows / Linux 的 ref 身份证明；解析前先看 version。
最重要的一条：ok: true 不等于效果发生。动作返回 delivered_unverified 时只说明输入已派发、后果尚未确认；只有重新读界面（get / is / 新快照）才算验证过。这也是它比一般 GUI 自动化脚本更可靠的地方。
07

分层架构与工程规范

调用方 Agent → CLI / C 库 → core → PlatformAdapter → 平台 crate → 目标应用。

  • 依赖倒置是硬规则：crates/core 定义 PlatformAdapter trait 和全部共享类型，crates/macos / windows / linux 各自实现；core 永不 import 平台 crate，平台 crate 之间也互不 import，只有 binary 与 FFI crate 能把两者接起来，平台在编译期由 cfg(target_os) 选定。
  • 仓库分层很清楚：src/ 是 CLI（cli / dispatch / batch / command_policy / mcp），crates/ffi/ 出 cdylib 与生成的 C 头文件，skills/ 编译进二进制，tests/ 放 golden fixtures 与各平台 E2E，probes/ 存真实平台测量，apps/docs/ 是文档站源码。
  • 一个命令一条链路：dispatch() 是一个直接 match，没有命令 trait 或注册表；batch 不是第二个 dispatcher，它反序列化成同一个 Commands enum 后走同一条路径；MCP 也不是第二套命令面，工具列表运行时从 clap 命令树读出。
  • CI 门禁会自测：scripts/check-architecture.sh 在 pre-commit 与 CI 中检查分层、目录布局、测试摆放等规则，扫描前会先植入每种违规样本 —— 哪条规则检测不出来了，门禁自己就失败。cargo 必须按 host package set 限定范围，clippy --all-targets -D warnings 零警告。
  • 代码规范近乎苛刻：手写 Rust 单文件 ≤ 400 行、禁止行内注释、禁止非测试代码里的 unwrap / expect / panic!、struct 最多 7 个字段、函数最多 5 个参数、测试文件必须放在代码旁边。
  • dogfood 要求「像陌生人一样用」：执行者只拿到发布版二进制和随附 skill，不给源码和计划；逐字运行文档里的每条示例，用工具自身的 wait 而不是 sleep，且「一份没有 finding 的报告算失败」。
成熟度：1.0.0（2026-10-27）补齐 Linux、成为跨平台里程碑；1.1.0 有破坏性变更（envelope 升 2.6、C ABI major 升 7）；1.2.0 加入 MCP 与 --stdin。仓库还有 208 个 open issue、Windows 部分 E2E 仍标注「需要 Windows 主机，尚未跑过」，属于活跃但快速演进的项目。
08

安全边界与适用判断

什么时候该用、有什么门槛，以及必须先知道的红线。

  • 隐私是首要风险：README 开头就警告快照、剪贴板读取、截图、命令输出和调试产物都可能含桌面上的私人内容，别丢进公开日志或上传；项目对诊断日志做脱敏门禁，密码框内容在观察与动作两侧都不回显。
  • headless 是安全默认值：不抢焦点、不移光标、不合成按键；POLICY_DENIED 表示 headless 挡下了物理路径，严禁为了「绕过失败」自行切到 --headed，需要物理输入必须由人显式允许。裸 --xy 坐标不带来焦点，调用方自己负责点到了哪里。
  • 权限与环境：macOS 要辅助功能（截图还要屏幕录制）；Windows 二进制未签名，SmartScreen 可能警告、杀软可能隔离，干净的 Win 11 上 Smart App Control 会直接拦，需手动关闭；Linux 必须在真实图形会话里跑，Wayland 下部分指针动作返回 ACTION_NOT_SUPPORTED。
  • 漏洞报告走私有通道：SECURITY.md 明确要求用 GitHub private vulnerability reporting，不要开公开 issue；范围含 CLI、npm 安装器、FFI 边界、发布产物、Actions 工作流与平台适配器。
  • 不适合谁：想自动化网页（用 agent-browser）、目标应用不暴露无障碍树、需要无人值守却不肯处理系统权限、或无法接受 1.x 阶段破坏性契约变更的场景。Windows / Linux 上「长得一样的双胞胎控件」目前也没有干净的 ref 路径。
  • 适合谁：要给本地 Agent 加「真实桌面 GUI 操作」能力、又希望每一步可验证、可判断能否安全重试的人；尤其在意「不靠截图猜坐标」和「输入是否送达有机器可读证据」的自动化场景。
建议姿势：先在无关紧要的本地应用上跑 status → skills get desktop → skills get platform，用 Quick start 的「画浅图 → 下钻 → 点一下 → wait 验证」完整走一轮，确认权限与交付判定符合预期后再接 MCP 或写进 AGENTS.md。
