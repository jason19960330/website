01

它到底是什么

不是「抓站工具」，而是一套写好的反向工程工作流：模板预置了 Next.js 16 + shadcn/ui + Tailwind v4 的工程骨架， 克隆动作由你的 AI 编码智能体（Claude Code / Codex / Cursor / OpenCode）按照内置 Skill 执行。

  • 交付的是代码，不是截图：截图、iframe、下载来的生产包只是参考，最终产出是可编辑、可维护的组件代码——这是它和普通「网页转图片/转 HTML」工具的本质区别。
  • 一条命令开工：把目标网址连同 /clone-website 指令交给智能体，它按固定工作流走完观察、复刻、对比、修复全过程。
  • 1:1 像素级优先：模拟阶段不做个人审美改动——先精确匹配间距、颜色、字体排版，之后再谈定制。
  • 真实内容：用源站真实的文字和素材（字体、图片、SVG、视频），不放占位符。
技术栈：Next.js 16（App Router · React 19 · TypeScript strict）· shadcn/ui · Tailwind CSS v4（oklch 设计 token）· Lucide React（克隆时被提取的真实 SVG 替换）· 部署目标 Vercel。要求 Node.js 24+。
02

快速开始

最省事的办法：把下面这段话直接丢给你的编码智能体（Claude Code / Codex 都行）， 它会替你完成克隆仓库、装依赖、跑检查的全过程。

  • 或者建自己的仓库：在 GitHub 上新建一个空仓库，把链接交给 Agent，让它 clone、装依赖并跑 npm run check。
  • 跑通检查再开工：npm run check = lint + typecheck + build 三连，全绿说明骨架没问题，可以开始克隆了。
  • 不想装 Node：仓库带 Docker 支持，docker compose up app --build 起生产、docker compose up dev --build 起开发（端口 3001）。
03

四步克隆工作流

内置 Skill（.agents/skills/clone-website/）把克隆拆成四步，每一步都有明确的完成标准。

  • ① Map · 规划：读项目结构与现有路由，用浏览器打开目标站，记录「源 URL → 本地路由」映射表和每个页面的文件归属；同源多页保留原路径，冲突先解决再动手。
  • ② Observe · 观察：桌面 + 移动宽度下通览整页、滚动触发懒加载、逐一验证交互状态，读取真实计算样式与 CSS 变量（详见第 04 篇）。
  • ③ Build · 复刻：先立字体、配色、页面宽度、共享组件（带齐 hover/focus/断点全部状态），再用真实内容逐段构建；CSS 优先做布局和简单动效，复杂行为才上动画库。
  • ④ Compare · 对比修复：源站与本地在「同一视口、同一滚动位置、同一状态」下并排比对，先修最大差异，直到生产构建通过且渲染对比通过（详见第 06 篇）。
在克隆指令里可以直接给多个网址：/clone-website <url1> [<url2> …]；同源的多页会被规划成一组路由。
04

先观察，再动手

这个模板最讲究的一步：把每一次观察当成一条「规则」的一个样本，读声明值而不是从单次渲染里猜。

  • 整页通览：桌面和移动宽度各来一遍，从上滚到下加载懒加载媒体、露出粘性/固定场景。
  • 真实输入驱动：用访客的方式操作页面——滚轮、触摸、键盘、指针；脚本化滚动会绕过绑定在这些输入上的行为（比如平滑滚动）。
  • 区分触发方式：一个变化究竟是滚动、点击、悬停还是时间驱动的？用点击模仿的滚动驱动区块，是另一个产品。
  • 读声明值：读计算样式、CSS 变量、组件库的实时 options，而不是从一次渲染反推；并变化视口宽度（包括比设计稿更宽）、输入和状态，直到弄清每条规则由什么驱动。
  • 证据存档：截图标注视口、滚动位置、交互状态；沉淀一份紧凑的页面简报（区块顺序、排版、布局测量、素材映射、交互清单）。
Framer 生成的页面、粘性场景、揭示动画、动效媒体有专门的参考文档（references/framer-and-motion.md），提取与状态对比见 references/inspection-guide.md。
05

真实素材与内容

用源站真实的文字和它真正加载的文件——同名替代品（别的字体厂、别的图标集）度量或形状都不一样。

  • 全套真实素材：字体、图片、SVG、视频都用源站实际加载的那份；克隆时默认图标库（Lucide）会被提取出来的真实 SVG 替换。
  • 先看分层素材再动手：重建视觉之前，先检查图层化的图片和媒体元素，别急着用 HTML 重画。
  • 资产映射表：维护「源 URL → 本地路径」的映射，并核实内容类型和尺寸——一个 .png 结尾的 URL 实际可能返回 AVIF。
  • 测量关键几何：重要的尺寸和计算样式要实测，不靠目测。
产出物落在 public/sites/<site>/（图片、字体、视频）与 src/components/sites/<site>/（组件与 SVG）； 研究证据落在 docs/research/<site>/（页面简报、资产映射、检查证据），截图存 docs/design-references/。
06

对比、修复、验收

验收标准不是「构建过了」，而是「构建通过 + 渲染对比通过」，并且要精确说出还剩哪些差异。

  • 同态对比：源站与本地页面在相同视口、滚动位置和状态下打开；等字体、媒体、揭示动画都稳定后再比。并排拼图定位漂移，全尺寸分段图看细节。
  • 先修最大的：修复顺序 = 几何 → 缺失区块/图层 → 排版换行 → 素材裁切 → 间距与动效；改完复查受影响的视图。
  • 动效三态对比：动画区域对比初始、激活、稳定三种状态，涉及反向滚动也要验。
  • 真实验收：跑生产检查（npm run check），走一遍真实的本地流程——路由跳转、移动菜单、标签/手风琴状态、轮播边界、主操作、媒体控制、滚动联动；查运行时报错、缺资源、横向溢出。
  • 诚实交付：明确说出剩余差异，不许把没验证的结果说成 pixel-perfect。
07

支持平台与项目结构

克隆工作流写成一个可移植的 Agent Skill，四个平台共用一份；Claude Code 走一个薄命令桥。

Claude Code（推荐 · 命令桥 /clone-website） Codex CLI OpenCode Cursor AGENTS.md 单一事实源 .agents/skills 可移植 Skill
  • 一份工作流多处用：Codex / Cursor / OpenCode 直接读 .agents/skills/clone-website/；Claude Code 通过 .claude/commands/clone-website.md 桥接，保证 /clone-website 命令可用且不向其他平台暴露重复副本。
  • 常用命令：npm run dev 开发 · npm run build 生产构建 · npm run lint · npm run typecheck · npm run check 三连检查。
  • 目录职责：src/app/ 路由 · src/components/sites/<site>/ 站点组件与提取的 SVG · public/sites/<site>/ 素材 · docs/research/<site>/ 取证 · scripts/ 素材下载脚本。

08

适用场景与边界

官方列了三类用途；同时要清楚它的边界和克隆他人站点时的合规底线。

  • 平台迁移：把你拥有的 WordPress / Webflow / Squarespace 站点重建成现代 Next.js 代码库。
  • 源码找回：站还在线上但仓库没了、开发者离开了、技术栈太老——用现代格式把代码拿回来。
  • 学习：用真实代码拆解生产站点如何实现特定布局、动效与响应式行为。
  • 明确的原则：像素级优先、模拟阶段不做个人审美改动、真实内容、每个像素都重要；交付时附运行说明、路由映射、对比截图、已跑检查与剩余差异。
  • 合规提醒：模板本身 MIT 许可；但克隆他人站点供个人学习、自有站迁移没问题，直接商用他人设计与内容需自行取得授权。
