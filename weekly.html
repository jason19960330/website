Self-hosted · 热点站框架

自建行业热点站

一个自己找热点、自己写日报的网站框架：每天从一批信源里收资料，先筛一遍、再独立打两次分， 挑出真正值得看的写成中文标题和摘要；把不同来源说的同一件事聚成一个事件， 按有多少人在说排出热点，每天早上出一份日报。 把信源和精选标准换成你的，它就是你的行业热点站。

01

它到底是什么

一个线上正在跑的热点站的完整框架：网站、后台、精选流程、聚簇和热度算法， 以及所有提示词的原文与入选门槛，都在同一个仓库里。

  • 不是 RSS 阅读器：不是把订阅原样堆给你，而是先判断值不值得看，再重写成中文标题与摘要。
  • 不是通用 SaaS：它是给「懂某个行业的人」准备的火种——你提供信源和口味，它负责流程和工程。
  • 提示词即配置：每一步的判断标准都是可以编辑的提示词文件，改标准不用改代码。
  • 同一份内容，人和 Agent 都能用：网页、RSS、公开 API、MCP、llms.txt 输出同一份精选。
一句话：工作流是它的，行业 KnowHow 是你的。把「哪些信源有用、什么消息才算热点」换成你的答案， 它就不是 AI 热点站，而是法律热点站、HR 热点站、贵金属热点站。
02

一条资料怎么变成精选

从信源进来先判重，再预筛；可能重要的用同一份标准独立打两次分，过了门槛才进精选； 然后重写为中文标题摘要、和别的报道聚成事件，最后进日报。

  • 1 · 收进来：同一网址、同一内容只留一份；只有标题或订阅摘要的，先抓原文页面再判断。
  • 2 · 预筛：判断是不是本行业的事。宽进严出，只拦明显无关的；拿不准的继续往下走。
  • 3 · 评分：同一份评分标准独立打两次分（0–100），两次之和 ≥ 2 × 门槛 才入选；页面上显示的分数是两次的平均。
  • 4 · 写标题摘要：入选的，以及差一点入选的（平均分高于下限），写中文标题、答案先行的摘要、推荐理由和标签。
  • 5 · 结构化：分类、标签、主体公司、事实（谁、做了什么、对什么），与评分同时进行；主题页和事件归组都靠它。
  • 6 · 归组与成刊：不同来源报道的同一件事归成一个事件，事件页有综述；入选资料要等归组完成（最多 3 分钟）才出现在精选里，避免同一件事先冒出好几条。
门槛 · T1 官方一手 60 门槛 · T1.5 官方账号 65 门槛 · T2 媒体与个人 76 重写下限 50
官方一手信源门槛低一些、媒体和个人高一些：同样一件事，官方原文更值得先看。 这组数偏严——宁可少选几条，也不让噪声进精选。换了行业一定要重新校准。
03

六种信源与信源分级

信源可以在后台新建、试抓、调频率、看失败原因；抓取频率会按产出自动调整。

RSS 网页列表（配选择器） JSON 接口 X 账号 微信公众号 脚本推送
  • 分级决定门槛：官方一手、官方账号与准官方、媒体与个人，以及不参与精选的分级——不同分级入选门槛不同。
  • 参与方式：进精选和全部动态 / 只作热度证据 / 不进任何公开页面，三种按信源设置。
  • 全文默认关：站内只展示摘要和原文链接，只有来源明确允许时才打开全文。
  • 公众号信源：国内很多行业的一手信息在公众号上，需要第三方接口凭据，按请求计费并带预算熔断。
真正常用的不是配置文件，而是后台的「信源」页：能一条一条试抓、看到为什么失败， 比改配置再重启容器快得多。
04

聚簇：同一件事只出现一次

官网发一篇、媒体转十篇、社交平台上吵一天，读者只需要看到一次。

  • 先找候选：用标题与摘要的向量，在最近两周里找可能的同类报道。
  • 再让模型判断：是同一件事、是后续进展，还是两件事；拿不准的先合并，换一家模型再确认一遍。
  • 进展挂在事件下：后续报道进同一个事件，事件页有综述。
  • 人工改过的不覆盖：人工调整过的归属关系不会被自动流程覆盖。
05

热度：按事件算，不按文章算

排在最前面的，是真正有很多人在说的事，而不是被转载最多的那篇文章。

  • 48 小时窗口：窗口内每个独立来源只算一次，满 24 小时后权重减半。
  • 重复抓取不加分：一家媒体发十篇也只算一次。
  • 社交讨论也算：公开平台上的讨论作为热度证据计入。
  • 状态标记：和 6 小时前相比涨得快的标「上升」，新出现的标「新」。
06

日报 / 周报 / 月报

按分类分节、带导语，按站点时区定时生成。

每天 08:00 出日报 每周一 10:00 出周报 每月 1 日 10:30 出月报 日报覆盖前一日 08:00 起的精选
  • 日报不是把当天的条目标题堆在一起，而是组织标题、导语、分类分节和数据来源。
  • 周报、月报按同一套模板产出，导语与分节规则可以单独调整。
07

给 Agent 用

同一份内容，给人看也给 Agent 用。

RSS：精选 / 全部 / 全文 / 日报 公开 API MCP llms.txt
  • MCP 工具名用站点前缀区分，例如前缀决定工具名为 前缀_get_latest 这类形式；有人接入之后就不要再改。
  • llms.txt 让 Agent 一眼知道这个站有什么、怎么取。
  • 另含模型榜等可开关的行业专属模块，别的行业一个开关关掉即可。

09

把它改成你的行业

要改的东西几乎都在行业配置那一个文件夹里，代码基本不用动。

  • 站名与文案：站名、行业词、首页标题与介绍、MCP 前缀、抓取时报的名字、关于页文案、备案号。
  • 分类、标签、主题：首页与「全部动态」的筛选类别、三类主题（公司与机构 / 方向 / 内容形态）、行业主体机构名单。
  • 信源：首次启动导入一批示范信源，之后主要在后台维护。
  • 精选标准（最值得花时间）：预筛、评分标准、标题摘要写法、术语翻译与保留规则、事件归组、日报导语与周报月报——全是提示词文件。

10

校准与使用须知

  • 必须重新校准：换行业、改评分标准后，用自己标注的 100–200 条样本评测——看准确率、查准率、查全率，以及门槛从 40 到 90 每一档的结果。
  • 留一组样本别看：调提示词只用开发集，最后用留出集复查，免得把标准调成「只会做这几道题」。
  • 多标难例：差一点就该选、差一点就不该选的。一眼能判断的放太多，准确率会虚高。
  • 标注的人最好是读这个站的人：口味一致，校准才有意义。
